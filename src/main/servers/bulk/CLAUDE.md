# Actions sur tous les serveurs (page Serveurs)

Menu « Tous les serveurs » (`pages/Servers/components/BulkActionsMenu.tsx`), doc utilisateur `docs/servers.md`. IPC `bulk:*` (`src/main/ipc/handlers/bulk.ts`), état poussé par `servers:bulk:changed`.

- **L'action tourne dans le main**, pas dans la page : elle continue fenêtre fermée ou page quittée, la page relit l'état au montage (`bulk:get`). État et demandes (« arrêter après », annulation) dans `bulkState.ts`, déroulé dans `bulkRunner.ts`. Une seule à la fois (`BULK_ACTION_RUNNING`). Un état terminé reste lisible jusqu'à `bulk:dismiss` : le renderer garde le bilan affiché tant qu'il n'est pas vu (sinon un échec, fenêtre fermée, passait inaperçu).
- Cibles **figées au lancement** (`bulkTargets`) ; `BulkStep.wasRunning` décide de ce qu'on fait au serveur. ⚠️ Statut **et PID** relus au moment de traiter chaque serveur, et de nouveau après la vérification Steam (jusqu'à 30 s) : démarré, arrêté ou relancé à la main entre-temps → `skipped`. Sinon SteamCMD écrivait dans un serveur lancé, ou un serveur arrêté exprès était relancé.
- **Mêmes chemins qu'un serveur seul** : `startServer`, `ServerManager.stop` (`bulkStepTools.ts`), et pour la mise à jour `checkServerUpdate` / `updateStoppedServer` (`src/main/server/serverUpdate.ts`, partagés avec le redémarrage planifié ; étape dans `bulkUpdateStep.ts`). Redémarrer = arrêter puis démarrer, pas `restartServer` : une annulation entre les deux ne relance pas le serveur.
- Un serveur après l'autre, un échec n'arrête pas les autres ; démarrages espacés de 5 s comme `autoStartServers`. Erreur hors d'une étape (config illisible) : les étapes restantes passent en échec, l'action se termine toujours.
- **Verrou partagé** avec le planificateur (`acquireRestartLock`, `src/main/scheduler/restartCountdown.ts`) : un serveur en compte à rebours planifié est passé (`busy`), et pendant l'action ni redémarrage planifié ni mise à jour trouvée ne le touchent. Chaque verrou est rendu dès son serveur traité (`held`, jamais celui d'un autre traitement).
- **Prévenir les joueurs** (`bulkWarnings.ts`) : annonces **en parallèle** pour les serveurs lancés qui ont un client d'annonce (`canAnnounce`), avec les annonces de leur Planification (`runCountdown`), puis arrêts un par un ; le dernier palier part avec la config d'arrêt de chacun (son « 1 min » peut arriver plus tard que prévu pour les derniers). « Arrêter après » pendant cette phase annule tout de suite les comptes à rebours (`stillWanted`) : sinon les joueurs recevaient toutes les annonces pour rien. Le renderer ne propose la case que si un joueur est connu en ligne (`bulk:onlinePlayers`, `ctx.getOnlinePlayers` : entrées `online` du suivi des joueurs, `null` sans source).
- **Logs** : la ligne d'action va dans la session d'un serveur lancé ; compte rendu de mise à jour et cause d'un échec par `ServerManager.logOutsideSession` (courte session pour un serveur arrêté, sinon ils n'iraient dans aucun fichier). Pas de session ouverte quand il n'y a rien à ajouter.
- **Fermeture de Nexum** (`src/main/server/quitGuard.ts`) : `cancelBulkRun` avant d'arrêter les serveurs (plus aucun démarrage ni relance : un serveur relancé pendant la fermeture mourait avec Nexum). Mise à jour SteamCMD en cours (`bulkUpdatingServer`) : boîte « Attendre la fin / Quitter quand même ».
- Pourcentage de SteamCMD (`parseSteamCmdPercent`, `progress: 42.35`) : ⚠️ format non vérifié sur une vraie mise à jour, barre indéterminée sans pourcentage.
