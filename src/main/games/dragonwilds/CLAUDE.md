# RuneScape: Dragonwilds

> Vérifié sur une vraie install (SteamCMD 4019830, build 1.0.1.1, octobre 2026, avec connexion d'un joueur). Le guide Jagex et le wiki se trompent sur plusieurs points (⚠️).

- **Exécutables** : lanceur `RSDragonwildsServer.exe` (racine, GUI) → `RSDragonwilds/Binaries/Win64/RSDragonwildsServer-Win64-Shipping.exe`. Le lanceur reste vivant tant que Nexum tourne et renvoie le code de sortie ; à la fermeture de Nexum il meurt, le `…-Shipping.exe` continue et est adopté au lancement suivant (en dev, il hérite du port de débogage d'Electron : relancer sur un autre port). ⚠️ `RSDragonwilds.exe` (cité par le guide) est le **client**. Préfixe de processus `rsdragonwildsserver`.
- **Arguments** : `-Port=<jeu> -BeaconPort=<beacon>` (script `entry.sh` du dépôt Docker `runescape/rsdw-dedicated`). UDP seulement (jeu 7777, beacon 8888 = jeu + 1111). Pas de `-log` (ouvre une console, n'apporte rien). Config : `dragonwildsConfig: { port, beaconPort, adminPassword, customArgs }` (`DragonwildsLaunchConfig`).
- **Config** : `RSDragonwilds/Saved/Config/WindowsServer/DedicatedServer.ini`, section `[/Script/Dominion.DedicatedServerSettings]`, ASCII/UTF-8 sans BOM, CRLF, en-tête `;METADATA=(Diff=true, UseCommands=true)`. Clés gérées (`dedicatedServerIni.ts`) : `OwnerId`, `ServerName`, `DefaultWorldName`, `WorldPassword`, `PlatformPolicy` (`Crossplay` | `PC` proposés ; énumération `EDomPlatformFamily` = Crossplay, PC, PlayStation, Xbox, Nintendo). Jamais touchées : `ServerGuid`, `bAllowSendingCrashDumps`, clés inconnues. ⚠️ `AdministratorList` (modèle Docker) n'existe pas dans le binaire.
- Le serveur **réécrit l'INI à chaque démarrage** (→ `lockWhileRunning` + refus côté main) et **retire `AdminPassword`** après l'avoir lu : Nexum le garde dans `dragonwildsConfig.adminPassword` et le réécrit avant chaque démarrage (`prepareDragonwildsStart`, `startChecks.ts`). Test du mot de passe admin avec un 2e joueur : issue #154. `validate` de SteamCMD ne touche pas l'INI.
- **OwnerId** = EOS ID (32 hex, « Player ID » en bas des Paramètres du jeu). Vide → le serveur reste lancé sans rien faire : démarrage refusé par Nexum. (Annoncé « bientôt facultatif » par Jagex : faux en 1.0.1.1.)
- **Mondes** : `RSDragonwilds/Saved/SaveGames/*.sav` (+ `.sav.backup`). ⚠️ Le serveur charge le monde dont le **nom inscrit dans la sauvegarde** vaut `DefaultWorldName`, sinon le crée (ni « le plus récent », ni « le nom du fichier » ; un fichier renommé est accepté). Nom lu par `saveHeader.ts` (`SAVE` + taille, bloc `CINF` ; un `.sav` de personnage n'a pas de `WorldName`).
- Carte **Mondes** (`WorldsCard`, page Sauvegardes, `worlds.ts` + `handlers/worlds`) : monde chargé, « Charger au démarrage » (écrit `DefaultWorldName`), import d'un monde solo (`%LOCALAPPDATA%\RSDragonwilds\Saved\SaveGames`) ou d'un fichier (`dialog:selectFile` + `defaultPath`) : ZIP des mondes du serveur, monde du même nom déplacé dans `Saved/SaveGames-replaced/<date>/`, copie, `DefaultWorldName`. Serveur arrêté obligatoire.
- **Arrêt** : ⚠️ aucun arrêt propre. CTRL+C ignoré, CTRL+Pause et fermeture de console → mort immédiate (0xC000013A) sans sauvegarde, `taskkill` sans `/F` refusé → `taskkill`. Autosauvegarde toutes les 5 min (`dom.StateSaveFrequencyMins`) : perte max 5 min.
- **Logs** : stdout incomplet → suivi de `RSDragonwilds/Saved/Logs/RSDragonwilds.log` (UTF-8 BOM, voir `src/main/logs/CLAUDE.md`). Lignes utiles pour le suivi des joueurs (issue #155) : `LogNet: Join succeeded: <nom>`, `LogDomMatcherSession: Player ADDED to session [<EOS ID>]-[<nom>]`. Contient le mot de passe du monde (masqué à l'export). Gros volume : `SpellHoming`, `SpellCollision`, `DomNetActIntIds` ≈ 55 %.
- **Rejoindre** : nom du monde dans « Mondes → Public » (sensible à la casse, `searchName` = `DefaultWorldName`) ou `IP:port`. Version du serveur = version du client, sinon le monde n'apparaît pas.
- Pas d'API ni de RCON, pas de mods serveur : ni page Joueurs ni Mods. 6 joueurs max. Dossier du client du jeu (`RSDragonwilds.exe`) non détecté comme serveur.
- Pare-feu : `Dragonwilds Server - Game (<port>)` / `Beacon (<port>)`, port dans le nom (`checkRule` ne vérifie que le nom).
- Config UI : `handlers/config` = vue fusionnée INI + `dragonwildsConfig` pour `ConfigPage`.
